# 映射設定：操作流程與人工測試

適用 #13。助理已自動驗證成功設定、歷史版本、雙視窗衝突、角色限制及 720px 畫面；不需要使用者重做這些測試。以下保留詳細步驟供自行查看，實際 Windows 原生 DPI、現場操作適合度與正式啟用決策仍需人員確認。

## 已準備的合成環境

使用交付訊息中的本機網址。若已停止，於專案根目錄執行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start_acceptance.ps1
```

入口使用正式 React build 與真實 HTTPS 中央 API；瀏覽器連接層替代原生憑證保管。只含合成案件，不接真實 HIS。原先測試 run 仍保存在 `%LOCALAPPDATA%\ClinicReporterAcceptance\case-queue-v1`，更新環境會建立新 run，不刪舊紀錄。

## 可選操作檢查

1. 開啟首頁的管理裝置入口，輸入 `SYN-ADMIN` 作為操作身分後連線，點「映射與啟用設定」。預期顯示「尚未設定啟用時間」、空白日期及確認過的 ERA／A059653100／易剋冒膠囊代碼鏈。
2. 在這個合成環境輸入三天前為生效日期與初始掃描起日，勾選啟用，原因填 `合成驗收首次設定`。按「儲存新版本」。預期顯示版本 1、明確 `00:00:00+08:00` 及原因，正式匯出仍未啟用。這不是診所正式 go-live 日期。
3. 另開第二個管理入口，連線並開同一設定頁。兩個視窗都應顯示版本 1。第一個視窗以兩天前為生效日期、取消啟用、填原因後儲存。預期兩個歷史版本都保留，初始起日固定。
4. 第二個視窗不重新載入，填相同生效日期及另一原因後儲存。預期顯示中央現行版本與草稿差異提示，草稿保留、儲存按鈕停用。按「重新載入並核對」後看到版本 2，草稿清空；若要重新啟用，明確填昨天的新版本及原因。
5. 開啟回報管理或醫師入口，預期沒有映射設定導覽。選擇管理者文字作為操作身分也不增加權限。
6. 確認 OPEN 項目仍顯示。不要把成功儲存映射當成實際 HIS、SMIS 或正式營運驗證完成。

## 需要人工判斷的部分

- 在實際 Windows 客戶端開啟同一功能，以診所慣用的 100%／125%／150% DPI 檢查標籤、按鈕、長原因及日期是否易讀，使用 Tab 與 Enter 檢查焦點是否清楚。瀏覽器測試不代表原生 DPI 已通過。
- 由負責管理者決定真正的啟用時間及初始範圍，並記錄核准依據。來源只提供日期，因此本版只接受台灣時間午夜的明確邊界；若現場需要日內切換，不可猜測醫令時間，應先補充可辨識邊界的契約。
- 回報問題時提供合成步驟、畫面文字與預期結果即可；不要傳真實病人、憑證、HIS 路徑或部署設定。
